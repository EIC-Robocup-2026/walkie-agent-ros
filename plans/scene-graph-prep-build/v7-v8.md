## V7: DetectObjects from a second detector

**Built.**

- `yolo.py`: `YoloeDetector`, a YOLOE instance with no tracker, and `untracked_detections_from_arrays`. It is built and warmed at start only with `on_demand_enabled`, so nothing loads late.
- `requests.py`: the `DetectObjects` checks, with 1 to 32 unique classes of 1 to 80 characters, `max_image_age_s` in (0, 1] and `timeout_s` in (0, 5]. It also holds `CurrentImage`'s newest colour and depth pair and `ClassPrepareGate`, which allows a new list at most once every 2 s, counted from the end of the last preparation.

- Config: `detect_objects_service` in `config/vision.yaml`, with `on_demand_enabled` false. `/walkie_vision/sim/detect_objects` in `config/sim.yaml`. `on_demand_enabled` true in `config/tasks/memory.yaml`. `launch/vision.launch.py` documents the service.

## Decisions, with what each costs

V7, from its commit:

- **A new list counts its 2 s from the end of the last preparation, and another new list before that gets `BUSY`.** Cost: a caller must retry a second new list.
- **The same ordered list prepares nothing.** A reordered list is a new list. Cost: a reordered list pays the full preparation.
- **The newest pair within the age limit wins over a newer image with no depth.** Cost: the answer can be one image older.
- **The second detector is built and warmed at start with the task's classes.** Cost: a slower start and its GPU memory for the whole run, with the flag on.
- **Every usable box in a `DetectObjects` answer is embedded.** This follows the brief. Cost: the embed time grows with the number of objects, up to 20.
- **Agent links name commit `91ffe25`, since no replacement page exists.** Cost: someone must update them when the agent owner publishes replacements.

V8:

- **`mask` includes the box copy.** The box copy is small next to the masks, and the copy happens in one place. Cost: `mask` is not purely masks.
- **The on-demand stage split shows in the c12 output, not in the node's line.** The node's line gets one `service` time per job. Cost: on the robot, a slow `DetectObjects` shows only its total.
- **Job stages print after `age`, and only when present.** Cost: none known.
- **Optional stages show only once they have samples.** The HRI line keeps its old form. Cost: a stage that never runs is silent, not shown as 0.
- **The load-failure warning names the model, the error type and the message, and the start still fails.** Cost: none known.
- **The c12 memory fixture holds depth that is already read.** Cost: the depth stage, the pairing and the queue are measured only on the robot.
- **The workflow uses the setup-pixi cache.** Cost: the environment is about 9.6 GB, and the runner's cache and disk limits are not checked yet.
- **`actions/checkout@v7`, as in `docs.yml`.** Cost: none known.
- **The workflow runs on push to `main`, on pull requests and on demand.** Cost: none known.
- **The workflow needs no `--clean-env`, because the runner starts clean.** Cost: it is not exactly the local command.
- **The pair-check doc names the prep paths `/var/tmp/wv-prep` and `/var/tmp/wd-prep`.** Cost: someone must change it to repository paths after the prep work merges.
