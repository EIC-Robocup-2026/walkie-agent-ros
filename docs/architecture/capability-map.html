What you can ask it

Each card is one thing a person can ask the agent, the tools it uses, the flags that turn it on, and where it has been shown to work. A card marked as works has run with the real model in at least one of the three places. In the fake world, gym runs means the real model called it in a Mahoraga gym run, oracle gate means only the gym's scripted oracle did, and tests means only tests against the fake robot did.

How it fits together

A request goes down these layers. The LLM sees only the tools. Each atomic calls a capability verb on ctx, which has a fake backend for tests and the gym, and a real one for the simulation and the robot: ROS wrappers for most verbs, and the wall clock and config.toml for ctx.facts. On ROS the grasp verbs only answer UNAVAILABLE, and --people-memory mock keeps the people store in process. update_todos and wait_for_person come from the runtime's middleware, and run_script from --scripts.

Tool sets

The LLM gets one set, chosen with --tool-set. Arm tools join a set only with --arms, which needs the hri or arms set, and the arms set needs --arms. update_todos and wait_for_person are always bound, and run_script joins any set with --scripts.
