## D3: lifecycle-ready object schema and ids

**Built.**

- `migrations/0004_object_lifecycle.sql`: map identity columns, `store_meta`, all object
  columns in the brief with the partial unique and link indexes, the map-row backfill,
  `object_geometry_invalid`, `object_label`, the observation view columns, `color_shares`
  checks, and `last_id` rebuilt to allow `object` with its insert trigger.
- `objects.py`: `reserve_object_ids`, `object_id_highwater`, `IdReservation`, `ObjectBox`,
  `NewObject`, `insert_object`, `tombstone_object`, `set_split_from`.
- `tests/test_migration_upgrades.py` and `tests/test_objects.py`. They cover the populated
  version 3 upgrade, running twice, a failing copy that rolls back, no reuse after a delete,
  a restart or a reservation, the commit order of a reservation and its PRAGMA changes, link
  and cycle checks, and a geometryless candidate staying out of `object_box`.
- Docs: `database.md`, `object-memory.md`, ADR-0011 storage contract, setup page 04.

**Existing test changed on purpose.** `test_last_id_keeps_the_largest_id_ever_given` now
expects the `("object", 0)` row, because 0004 adds that counter.

**Deviations.**

- The slice row asks for an ADR-0019 update. ADR-0019 was Accepted in D1, and accepted ADRs
  are not rewritten, so it was left alone. The storage contract is in ADR-0011 (Proposed) and
  `database.md`.
- `color_shares` element rules are triggers, because a `CHECK` cannot hold a subquery. The
  column `CHECK` covers a valid JSON array of length 12.
- The brief says to restore NORMAL after a reservation. `reserve_object_ids` restores the
  previous value instead. That is NORMAL on a file from `connect()` and FULL on `:memory:`.
- Generating a new `store_id` on node start and resetting the publication sequence are not
  built. The table exists. Node startup belongs to D6, and the node is unchanged in D3 to D5.

**Decisions.**

- `anchor_offset` and `expected_pose` also get a JSON validity `CHECK`, because `ADD COLUMN`
  is the cheap moment. Cost: a later non-JSON format needs a rebuild.
- `object_label` is not backfilled. A reader unions `object.label` until labels accumulate.
  Cost: D8 must do that union.
- `Refused` is reused from `people.py`. Cost: `objects.py` imports `people.py`.
- The ids a connection has used are tracked in a TEMP table, so a rollback frees an id and a
  delete does not. Cost: a reservation is tied to the connection that made it.
- A tombstone keeps its `object_box` and cloud, and readers filter by state. Cost: D8 must
  filter. A second tombstone on one object is refused.
- `store_meta.clock_kind` has no `CHECK`, exactly as the brief writes it.

**Unverified.** Real power-loss durability is a hardware limit, as the brief says. The tests
check the PRAGMA and commit order only. Legacy `find_objects` is unfiltered, so once M1 writes
tombstones or geometryless rows it would return them, the latter at position zero.

## D5: rooms, surfaces, catalogue, relations and events

**Built.**

- `migrations/0006_object_context.sql`: `room.key`, `surface`, `object.enclosed`,
  `object_catalogue`, `catalogue_alias`, `object.catalogue_id`, `object_relation`, `object_event`,
  `event`, `event_fts` with insert, delete and update triggers, `session_forget_events`, and
  `write_request`.
- `object_context.py`: `set_room_shape`, `room_outline`, `room_at`, `room_by_key`, `add_surface`,
  `usable_surfaces`, `add_catalogue_item`, `find_catalogue_items`, `link_catalogue`,
  `object_weight_g`, `set_relation`, `relations`, `add_object_event`, `object_events`, `add_event`,
  `find_events`, `canonical_json`, `payload_hash`, `find_write`, `record_write`, `WriteConflict`.
- `objects.py`: `require_transaction`, replacing four copies of the same check. Messages unchanged.
- `tests/test_object_context.py` (152 tests): polygons, room keys against display names, the
  cascade and set-null matrix, surface-target links, catalogue aliases, word index after insert,
  update, delete and rollback with FTS5 `integrity-check`, MATCH syntax refused, forgetting
  through `end_session` and `start_session`, ledger conflict, bounds and restart.
- `test_the_foreign_key_alone_would_keep_the_text` drops the trigger and shows the line survives
  with no person, so the privacy tests have teeth.
- `tests/test_migration_upgrades.py`: populated upgrade to 6, running twice, a failing copy rolled
  back on the same connection and after a restart, upgraded against fresh schema at 4, 5 and 6, and
  `integrity_check` and `foreign_key_check` after a one-go upgrade.
- Docs: ADR-0021, ADR-0022, both embedded in `database.md`; new sections there; setup page 04;
  demo size note on setup page 06, measured at 9,166,848 bytes on a throwaway seed.

**Deviations.**

- `session_forget_events` deletes more than the brief's rule. The brief deletes
  `WHERE session_id = old.id AND person_id IS NOT NULL`. The trigger also deletes an event naming a
  guest of this session under any other session or none. Otherwise raw SQL could leave a guest's
  line with `person_id` NULL, which is the outcome the rule exists to prevent. `add_event` refuses
  to write such a row, so this matters only for rows written by other SQL.
- `event` is stricter than the brief's bare columns: `text` has `CHECK` length 1 to 512, from
  `Event.msg`, and `x`, `y`, `yaw` are all or none, from `has_robot_pose`.
- `surface`, `object_relation` and `event` get indexes and triggers the brief implies but does not
  list: `surface_anchor_check` also requires `layer = 'anchor'`, and `surface_anchor_fixed` and
  `object_relation_fixed` refuse moving a row, since the checks otherwise run only on insert.

**Decisions.**

- ADR-0021 and ADR-0022 are Proposed, not Accepted as ADR-0019 and ADR-0020 are. D8 builds the
  readers and may need to amend them. Cost: someone must accept them, and D6 onward already depends
  on the schema they describe.
- `room.key` is plain nullable with a unique index. Cost: legacy rooms cannot be found by key until
  seeded.
- `surface.geometry_valid` and `surface.outline` default to 0 and `[]`, so a named surface can exist
  unmeasured. Cost: readers use `usable_surfaces`.
- Relations stay stored when an anchor stops being usable, and readers hide them. Cost: the row can
  be stale when the anchor returns. The alternative deletes evidence.
- `inside` needs `enclosed = 1`, checked in the helper and in `relations`, not in a trigger. Cost:
  raw SQL can store it, and it stays hidden.
- A catalogue link across maps is refused in the helper, not a trigger. Cost: raw SQL can write one.
- Aliases are stored normalised (casefold, single spaces), and official names match exactly. Cost: a
  lookup by official name is case-sensitive unless the name is also an alias.
- `object_event` has no state `CHECK`, so a later lifecycle can add states. Cost: nothing stops a
  typo in raw SQL.
- Event kinds, ledger sizes and `MAX_EVENT_RESULTS` (100) live in helpers, so they change with no
  rebuild. Cost: raw SQL gets past them. `max_results` of 0 is refused, and D8 must decide what the
  wire value 0 means.
- `since` is inclusive in `find_events`. The contract does not say. Cost: a poller sees its last
  line again.
- Ledger bounds: payload 16 KiB, outcome 4 KiB, 64 array items, 1,024 string characters, 128-character
  request id, 8 levels. They are my numbers. Cost: a larger legitimate payload is refused until the
  constants change.
- The payload hash covers the payload only, and the operation is compared as its own column.
- Punctuation-only search words are ignored by FTS5, so `plate (` finds plate, and `(` alone finds
  nothing. Every other word must match.
- `event.id` is a plain `INTEGER PRIMARY KEY` as the brief writes it, so SQLite can reuse the newest
  id after a delete. Cost: a recorded outcome can name an id that later means another line. ADR-0022
  records it.
- A person deleted alone keeps the line with no person, per "other references SET NULL". Nothing in
  `people.py` deletes a person alone today.

**Unverified.**

- Nothing calls these helpers from the node. `near`, `in_room`, the current-id resolver and FindNear
  remain D8.
- `write_request` is not cleared by anything yet. The offline restore that clears it is D6.
- The claim about FTS5 shadow and free pages comes from how SQLite and FTS5 work and the brief's note.
  I did not inspect the file's bytes after a forget.
- No room outline from a real map was tried. Crossing edges are not detected.
