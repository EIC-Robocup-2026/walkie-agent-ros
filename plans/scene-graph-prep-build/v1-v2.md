## V1: freeze the types

### Built

- `ObjectDetection.msg`, `ObjectDetectionArray.msg`, `EmbedText.srv`, and new `DetectObjects.srv`, `EmbedCrop.srv`, `DescribeCrop.srv`. A script compared each file with its block in brief section 3, and all six are identical line for line.
- `convert.py`: `new_stream_id`, `to_point_cloud`, `empty_cloud`, `check_object_detection_array`. `to_object_detection` takes `view_quality` and `color_shares`. `to_object_detection_array` requires the keyword `stream_id` and runs the check.
- The check refuses: a bad stream id, bad classes, a `camera_info`, cloud or sampled-crop header that differs from the array's, a label outside classes, a score or quality outside [0, 1] or not finite, a bad bbox, a vector without its model or the reverse, a wrong CLIP length, a vector that is not finite or not unit length, bad colour shares, a wrong cloud layout, width or data, and a crop that is not a JPEG.
- `pipeline.py`: one stream id per pipeline. An object score outside [0, 1] is dropped and counted.
- ADR-0013 embedded on `vision.md`. Updated `vision.md`, `docs/setup/02-message-package.md`, `CLAUDE.md`.

## Deviations

1. **No wire contract change after V1.** The brief's types are unchanged.
2. **Recipe commands do not work as written (brief lines 997, 1011).** Under `--clean-env`, `PATH` holds only the pixi environment's `bin`, which has no `env` or `bash`. The commands use `/usr/bin/env` and `/usr/bin/bash` instead. colcon's prefix script also calls `env`, so the build appends `/usr/bin:/bin` to `PATH`, after the pixi directory.
3. **V1 also changed `pipeline.py` and `tests/test_pipeline.py`, which its row does not list.** Without them, the real node's arrays would have no stream id and `convert` would refuse them. The score drop is there for the same reason: it keeps one bad model score from failing the whole frame. Before this, a score above 1 was published.
4. **V1 and V2 also changed docs outside their rows:** `docs/setup/02-message-package.md`, `CLAUDE.md` and `README.md`, which would otherwise be wrong.
5. **The real node's QoS does not follow brief line 145.** It says observation publishers are BEST_EFFORT, KEEP_LAST 1 on both paths. `node.py`'s `OUTPUT_QOS` stays RELIABLE, KEEP_LAST 5, because `node.py` is in neither row and existing tests and docs rely on it. It still matches a BEST_EFFORT subscriber, so nothing breaks on the wire. No later slice row names this change, so someone needs to assign it or correct the brief.
6. **ADR-0013 was edited after it was accepted, in V2.** The V2 row asks for this section. It only adds text, and the decision bullets did not change.

## Decisions

Each choice the brief left open, with what it costs.

**V1**

- `stream_id` is made in `VisionPipeline`, and can be injected. Cost: V7's on-demand path must read `pipeline.stream_id` and not make its own.
- `stream_id` is a required keyword on `to_object_detection_array`. Cost: a caller must change. There are no others here or in walkie-agent-ros (`git grep`).
- The check refuses a non-canonical UUID, such as an upper-case one. Cost: it is stricter than the message comment. A consumer sets its own rule.
- An empty crop gets the array's header from the builder, but the check only compares the header of a nonempty crop. Cost: a hand-built array with an empty crop and another header passes.
- Vector length is checked only for known real models, on object vectors. `EmbedText` limits wait for V6. Cost: a fake vector may have any length.
- The check walks each cloud on every array. Cost: small numpy work per detection, nothing while clouds are empty. It is not measured on the robot.
- ADR-0013 is Accepted because the types are in effect. Later slices add status text, not decisions.

**V2**

- "Seeded two-box fixture": there is no random number generator, because the ray cast needs none. Cost: none; determinism is tested directly.
- Determinism is tested by message equality, with the cloud and crop bytes compared too, not by serialized bytes. CDR leaves its padding bytes unset, so two serializations of one message can differ. Cost: none for consumers. A consumer must not compare serialized bytes either.
- Crops default on, vectors default off, as the pair gate needs a point and crop observation with an empty embedding. A vector needs a `fake_` name.
- `view_quality` is a scene value, so the formula has one home in V4. Cost: the fake does not exercise that formula.
- `color_shares` is one-hot from the scene, and empty under 50 pixels or without a colour. `PALETTE_RGB` holds the brief's colours. Cost: V5 should move that table to its colour code instead of copying it.
- A box a phase leaves out is removed from the render, so it hides nothing.
- Each phase has a `frames` count, which the brief does not name. Cost: one more scene field.
- The camera is static and its transform is on `/tf_static`, on by default. Cost: a test that needs a moving camera needs its own fixture. `tf2_msgs` comes through `ros-base`, so `pixi.toml` has no new dependency.
- The task hard-sets Fast DDS, localhost and domain 77. I checked that a shell `ROS_DOMAIN_ID=23` does not override it. Cost: `ROS_DOMAIN_ID=78 pixi run fake-detections` silently stays on 77, so the guide gives the other form.
- The clock: a frame is skipped when the clock reads 0 or has not moved since the last frame. A clock that goes back still publishes. Cost: a consumer can see stamps go backwards after a sim reset.
- "Fake profile" is read as the guide section and the task, with no config profile file.
